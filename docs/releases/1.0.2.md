# Atraxis 1.0.2

The terminal installation wizard prepares a private installation from a host-controlled policy. Operators can review sources, credentials and network settings before choosing preparation only, Docker Compose or native systemd.

Compose deploys Atraxis and its HTTPS proxy for read-only inventory. Native installation starts one systemd user service with TLS. Both paths check that anonymous requests are refused and that an authenticated readiness request succeeds.

See the [installation guide](../setup.md#guided-preparation-in-the-terminal) for host prerequisites, storage aliases, terminal screenshots and service management. Existing Compose installations with Atropos keep their separate operator procedure.

## Qualification

On the operational pilot, this runtime collected fresh observations from all
four configured sources. A distinct isolated host restored ten services and two
SQLite databases, verified account and audit state, renewed web and engine TLS
certificates, and rejected a revoked login while accepting its replacement.
Both execution queues stayed paused with zero workers during the restore.

The synthetic endurance run completed 237 rounds over two hours. Its engine
inputs and the pilot configuration are recorded separately from the operator
Compose stack. That stack pairs the published Atraxis 1.0.1 web image and its
1.0.0 client with the Atropos 1.0.1 engine and workers.
