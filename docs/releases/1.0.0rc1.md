# Atraxis 1.0.0rc1

First prerelease checkpoint toward Atraxis 1.0. This candidate packages the
existing supervision and operator interfaces; it is **not a stable-production
release**. The matching Atropos engine/client remain alpha dependencies.

Included: read-only source inventory, authenticated web/API/CLI/Textual flows,
scoped accounts and inventory grants, rule editing/scenarios/explicit lifecycle
through Atropos, and the documented verified-TLS Docker Compose installation.

Inventory includes direct `monit_docker` and `certlord` connections, plus optional
`prometheus_monit` and `prometheus_certlord` routes that preserve complete native
projections through Covenant and Prometheus, including certificate domains,
versions and fingerprints. Direct connections remain recommended and require
neither service. The generic `prometheus` adapter remains a numeric-metric source.
The indirect routes require Covenant's new observation plugins; the previously
published Covenant `0.0.72` does not include them. Use the source revision specified
in the candidate support matrix. Resource discovery is automatic within each
source inventory; transport capacity and Prometheus retention costs still need
qualification for the intended workload.

The reference target is Linux amd64, Python 3.11/3.12 packages, and Python 3.12
Compose with SQLite accounts/engine storage and the integrated queue. Existing
optional SQL/Redis adapters remain available with their documented limits.
The 1.0 language choice is the existing version-1 YAML rule/workflow models with
ZEN 2.1.2; no second language or arbitrary action scripting is added.

The attached wheel and source archive are the exact artifacts from the successful
installed-package qualification, not a later rebuild. `candidate-provenance.json`
identifies source commits, successful workflow runs and archive hashes;
`SHA256SUMS` verifies the attached files. Source trees at the qualification commit
and release tag are checked for equality before publication.

## Install

Download the wheel attached to this release and install in a fresh Python 3.11
or 3.12 virtual environment on Linux with the system libmagic library installed:

```sh
python -m venv .venv
. .venv/bin/activate
python -m pip install ./atraxis-1.0.0rc1-py3-none-any.whl
atraxis --help
```

This command installs the base package. Optional rules/engine and Textual
configuration follow the guides; it does not start services or execute actions.
See the [candidate support matrix](https://github.com/decryptus/atraxis/blob/v1.0.0rc1/docs/v1-candidate.md),
[setup](https://github.com/decryptus/atraxis/blob/v1.0.0rc1/docs/setup.md) and
[Compose guide](https://github.com/decryptus/atraxis/blob/v1.0.0rc1/docs/docker-compose.md).

## Before stable 1.0

Operational installation and complete recovery on a distinct host, approved live
execution/notification destinations, and the remaining workload/history checks
for that exact profile are still open. Synthetic CI effects and receiver
acceptance do not qualify live interventions or human receipt. Existing measured
workloads retain their original scope; this release makes no production-capacity
or general long-term stability promise.

Formats remain experimental during the candidate phase. Unsupported formats are
rejected without automatic migration or deletion. Keep backups and do not replace
an existing production deployment merely because a candidate is available.
