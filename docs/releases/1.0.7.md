# Atraxis 1.0.7 — qualification verified

This candidate fixes failure-table saturation and cross-client account lockouts.
The oldest failure entry is evicted at capacity. Behind a trusted ingress,
client-address/account budgets replace the shared proxy/account budget.

## Upgrade requirements

Upgrade the application and proxy configuration together. The immediate trusted
proxy must overwrite `X-Forwarded-For` with `$remote_addr`. Atraxis requires exactly
one valid address from that proxy and rejects missing or ambiguous headers.
Keep the application port private and restrict `trusted_proxy_networks` to the
actual immediate proxy. Do not append user-supplied forwarding chains.
Direct clients cannot spoof the limiter key. NAT-sharing and process-local limits
remain; eviction can discard budgets under churn, so retain ingress rate limits.

## Qualification and publication

The correction passed 574 local unit tests and all 45 candidate PR checks,
including nginx client isolation and separate-host Compose recovery. Two-hour
endurance completed 240 rounds over 7206.43 seconds, with final recovery verified.
The exact 1.0.7 wheel read four current pilot sources and restored ten services,
two SQLite databases and eight persistent trees on a distinct isolated runner.
Accounts, audits, TLS renewal, copied-login revocation and authentication throttling
passed. Both restored queues remained paused with zero workers. The live pilot
recovered and temporary private copies were removed.

G1, G2 and G3 are closed for this bounded reference scope in
[the qualification manifest](1.0.7-qualification.json). This does not establish
arbitrary production capacity, external delivery or high availability.
Registry and installer image pins are promoted separately after registry
verification. This release does not upgrade existing production deployments.
