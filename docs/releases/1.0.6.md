# Atraxis 1.0.6 — qualification pending

This release candidate contains the nginx and Basic authentication correction
merged in [PR #42](https://github.com/decryptus/atraxis/pull/42). Trusted ingress
failures are separated by account, nginx limits actual TCP client addresses,
and active rule forms are limited to four per account/controller. The same-account
failure window, direct-peer limits, bounded memory and single-use forms remain.

The exact 1.0.6 wheel read four current sources before a fresh, explicitly
authorized cold capture. On a distinct isolated runner it restored ten services,
two SQLite databases and eight persistent trees. Accounts and audits matched;
TLS renewal, revoked copied credentials, replacement access and login throttling
passed. Both queues remained paused with zero workers and no execution resumed.
Final source authority and deletion of the temporary private copy were verified.

The aggregate evidence archive matches GitHub SHA256
`74bf4e6db904b4b6d2edf03948bab2e6c4c81955ff9f0b419a317ea1b263e180`.
The source streamed the archives; its metadata-space guard and the receiver's
capacity guard remained enforced. No pilot service was deployed or upgraded.
The restored copy did not refresh external live sources or verify external
delivery. This qualification does not repair the separate nightly-backup
infrastructure or extend the support matrix to arbitrary deployments.

## Retained preparation failures

The initial source Compose build refused a stale expected application version
in its environment lock. The lock was corrected to 1.0.6 without changing other
dependencies or bypassing the guard. A candidate-verification job also refused
the historical package archive before operational access; its archive pin was
aligned with the exact 1.0.6 candidate. Both corrected procedures passed before
the authorized operational qualification.

## Delivery sequence and remaining image pins

After all gates and the final PR workflows pass, publish GitHub assets, then the
matching Docker image, then promote the exact GitHub distributions to PyPI with
their real hashes. Verify a fresh registry installation and update the existing
EN/FR site only after publication. Existing release tags remain immutable.

The guided installer still references the qualified 1.0.5 image, and the separate
registry Compose starter still references its qualified 1.0.1 images. Publishing
1.0.6 does not update those pins automatically. Their subsequent upgrades must
use the actual qualified digest and pass deployment acceptance. Changing the
packaged installer after qualification changes the wheel payload and requires
qualification of that changed package; do not silently substitute it.

Atropos is unchanged. Published installation instructions and the website continue
to describe 1.0.5 until this candidate is qualified and released.
