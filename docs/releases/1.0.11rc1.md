# Atraxis 1.0.11rc1 — release candidate

Native `monit_docker` sources support three explicitly selected outbound authentication modes with `auth_mode`: `basic` (the default), `bearer` API tokens, and `none` for intentionally public read-only inventory. Existing Basic configurations remain valid. No credential fallback occurs after a 401/403 and credentials are never forwarded on redirects. Other adapters and inbound Atraxis authentication are unchanged; TLS and redirect restrictions remain in force.

For Monit-Docker 2.x SQLite authentication, use a private ASCII token file with the `status:read` scope and `auth_mode: bearer`. For a deliberately public source, use `auth_mode: none` and omit `credentials_file`. See the [source configuration guide](../source-configuration.md). Preserve source IDs, inventory grants and existing data when changing a source connection.

The source distribution now contains only what is needed to build, install and run Atraxis; repository, test and maintainer files are no longer included.

The package now supports Python 3.11 to 3.15 (tested on 3.14 and 3.15). It requires DWho 0.3.70 and HTTPdis 0.7.2, and the optional rule client is Atropos client 1.0.6. Atropos 1.0.1 and later report an inaccessible rule as not found (HTTP 404) rather than forbidden. Runtime images stay on Python 3.12.

## Qualification and delivery

This is a GitHub prerelease of the exact tested archives; it is not published to PyPI or Docker Hub and is not a stable release. The implementation PR passed all eleven required workflows. The runtime changes are not covered by earlier operational evidence: the two-hour endurance gate (G3) runs automatically on this candidate wheel, and live-source (G1) and isolated cold-recovery (G2) evidence must be produced for the same wheel before 1.0.11 can be published. No registry publication, pilot migration or fresh backup success is claimed. The guided installer and Compose starter keep their previously qualified image pins.
